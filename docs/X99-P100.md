# X99 with two or three Tesla P100s

The IQ3_S engine splits every selected expert across all active cards. Its 640 intermediate columns occupy twenty quantization blocks. Two cards take ten blocks each. Three take seven, seven and six (224/224/192 columns). The down-projection kernel handles the final 32 columns of each 224-column slice. The three-card profile uses the general prompt path and lets the engine size its expert cache to available VRAM.

## Build and prepare

From the repository root, choose the number of cards for the session. Use a separate build directory for each count. The two configurations can share prepared model files on NVMe.

```bash
export CARDS=3                          # Set to 2 for the two-card run
export CUDA=/usr/local/cuda-12.9
export HOSTCXX=/usr/bin/g++-13
export B="$PWD/build/$CARDS"
export DATA=/path/on/nvme/flash-next
export LD_LIBRARY_PATH="$CUDA/lib64${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"

bash build.sh
bash setup.sh "$DATA"
PROFILE="$DATA/profile.json"
if [ "$CARDS" = 3 ]; then PROFILE="$DATA/profile-3gpu.json"; fi
bash run.sh "$DATA" --config "$PROFILE" --port 18080
```

Setup keeps existing profiles. Check the executable and GPU indices in the selected JSON when reusing a data directory. The measurements use the full model, a 524,288-token context, MTP, lookup 15 and exact routing.

## Reproduce the timing

Run this in a second shell with the same DATA value. Start each comparison with a freshly loaded model and keep the API idle apart from the benchmark.

```bash
python3 bench/bench.py --strata-dir "$DATA/strata-v0.2.9" \
  --url http://127.0.0.1:18080 --wait 6 --ours iq3_s \
  --tests fresh,edit,long,medium,image --out "$DATA/benchmark-$CARDS.json"
```

## GPU regression

With the same build environment as above, build the optional test. It compares compact and zero-padded down projections for four weight formats, including the 192- and 224-column slices. A 96-row build exercises 392 cases.

```bash
cmake -S . -B "$B" -DSTRATA_BUILD_TESTS=ON
cmake --build "$B" --target split_p100_tail_test -j 2
"$B/split/split_p100_tail_test"
"$CUDA/bin/compute-sanitizer" --tool memcheck --error-exitcode 1 "$B/split/split_p100_tail_test"
```

## Optional two-card lookup experiment

Set `FNX_LOOKUP_SOURCES` to `"4"` in the profile's `env` object to search the last four matching trigrams. The engine chooses the candidate with the longest matching history that agrees with the first draft token. Equal lengths favor the newest occurrence. The default of one source reproduces the upstream lookup policy. This experiment keeps the existing verifier and lookup length. It adapts the selection rule from [Basalt's suffix drafter](https://github.com/jesdga95/basalt/blob/899e820af777705cd29b35b1deb8612f24c42c5e/src/spec/suffix_drafter.cpp).
